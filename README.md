# AIL (Archive Image Library) Format

AIL — это высокопроизводительный формат архивации изображений, оптимизированный для быстрого просмотра, экономного использования памяти и защиты данных.

## Особенности формата
- **Мгновенный просмотр**: Встроенная секция превью (thumbnails) позволяет галерее отображать содержимое без распаковки основных данных.
- **Асинхронная загрузка**: Декодирование изображений и создание текстур вынесено в фоновые потоки, что обеспечивает 60+ FPS интерфейса.
- **Эффективное сжатие**: Поддержка алгоритмов Zstd и LZ4.
- **Защита данных**: Прозрачное шифрование AES-256-GCM.

## Структура файла (.ail v2)

Файл имеет строго детерминированную бинарную структуру, оптимизированную для последовательного и произвольного доступа. Все числовые значения записываются в формате **Little-Endian**.

### 1. Header (Заголовок) — 32 байта
Заголовок всегда находится в начале файла и имеет фиксированный размер.

| Смещение | Размер | Тип | Описание |
|----------|--------|-----|----------|
| 0 | 4 | [u8; 4] | Магическое число `AIL!` |
| 4 | 4 | u32 | Версия формата (текущая: 2) |
| 8 | 1 | u8 | Флаг шифрования (0 - нет, 1 - AES-256-GCM) |
| 9 | 3 | [u8; 3] | Зарезервировано для выравнивания |
| 12 | 4 | u32 | Общее количество изображений в архиве |
| 16 | 8 | u64 | Смещение секции превью от начала файла |
| 24 | 8 | u64 | Размер секции превью в байтах |

### 2. Thumbnail Section (Секция превью)
Используется галереей для мгновенного отображения обложки.

- **Thumbnail Header (20 байт)**:
    - `width` (u32): Ширина превью.
    - `height` (u32): Высота превью.
    - `compression` (u8): Тип сжатия (всегда Zstd для v2).
    - `reserved` (3 байта): Резерв.
    - `data_size` (u64): Размер зашифрованных и сжатых данных.
- **Thumbnail Data**: Данные изображения (JPEG), сжатые Zstd и зашифрованные AES-GCM.

### 3. Index Section (Секция индекса)
Содержит метаданные всех файлов. Находится сразу после секции превью.
Представляет собой последовательность записей **AilEntry**.

**Структура одной записи (AilEntry):**
1. **Имя файла**: Строка UTF-8 переменной длины, заканчивающаяся нулевым байтом (`\0`).
2. **Тип сжатия** (1 байт): 0 - None, 1 - Zstd, 2 - LZ4.
3. **Reserved** (3 байта): Резерв.
4. **Original Size** (u64): Размер файла до сжатия.
5. **Compressed Size** (u64): Размер файла после сжатия (и до шифрования).
6. **Data Offset** (u64): Абсолютное смещение данных этого файла от начала архива.
7. **MD5 Hash** (16 байт): Хеш оригинальных данных для проверки целостности.

### 4. Data Section (Секция данных)
Самая большая часть файла, содержащая фактический контент.

Каждый блок данных в этой секции организован следующим образом:
1. **Nonce (12 байт)**: Уникальный вектор инициализации для AES-GCM.
2. **Encrypted Payload**: Данные, которые были сначала сжаты (Zstd/LZ4), а затем зашифрованы.
3. **Auth Tag (16 байт)**: Автоматически добавляется AES-GCM в конец Payload для проверки того, что данные не были изменены.

## Алгоритм обработки данных

### При создании (Encoding):
1. **Сортировка**: Файлы сортируются по имени (Alphanumeric sort).
2. **Сжатие**: Каждый файл сжимается выбранным алгоритмом (Zstd по умолчанию).
3. **Шифрование**: Сжатый блок шифруется AES-256-GCM с использованием ключа из `key.bin` и случайного Nonce.
4. **Запись**: Nonce и зашифрованные данные пишутся в Data Section, а смещение фиксируется в Index Section.

### При чтении (Decoding):
1. **Поиск**: По индексу находится смещение и размер нужного файла.
2. **Дешифрование**: Читается Nonce, данные расшифровываются ключом из `key.bin`.
3. **Декомпрессия**: Расшифрованные данные разжимаются в оригинальное изображение.
4. **Отрисовка**: Изображение конвертируется в пиксели и передается на GPU.

## Шифрование

В формате используется алгоритм **AES-256-GCM** (Authenticated Encryption with Associated Data).

### Управление ключами
- Ключ генерируется автоматически при первом запуске программы и сохраняется в файл `key.bin` в корневой директории.
- Длина ключа: 256 бит (32 байта).
- **Внимание**: Без файла `key.bin` расшифровка архивов, созданных вашей копией программы, невозможна.

### Процесс обработки данных
1. **Кодирование**: `Raw Data` -> `Compression (Zstd/LZ4)` -> `Encryption (AES-GCM)` -> `File`.
2. **Декодирование**: `File` -> `Decryption (AES-GCM)` -> `Decompression` -> `Raw Data`.

Для каждого блока данных (включая превью) генерируется уникальный 96-битный **Nonce**, который записывается непосредственно перед зашифрованными данными.

## Технические требования
- **Язык**: Rust
- **Графический движок**: egui / eframe
- **Ключевые зависимости**: `zstd`, `lz4`, `aes-gcm`, `image`.

## Использование
1. Поместите изображения в папку или используйте ZIP/RAR архив.
2. Используйте встроенный кодировщик для создания `.ail` файла.
3. Откройте папку с `.ail` файлами в галерее для просмотра.
